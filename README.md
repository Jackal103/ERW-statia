# Сравнение скорости C++ полиморфизма на ESP32: vtable против std::variant

В этом репозитории лежит мой код для УИР (статьи), где я сравниваю два способа сделать полиморфизм на микроконтроллерах ESP32: 
1. Классический через виртуальные функции (**vtable**).
2. Современный статический через **std::variant + std::visit** (из C++20).

## Результаты тестов

Я написал бенчмарк, который симулирует опрос **250 датчиков** подряд, и замерил время. Вот что получилось:
* **Обычный vtable:** Оказался быстрее.
* **std::variant:** Отстал и получился **медленнее примерно на ~200 мкс** за весь цикл опроса.

### Почему вариант проиграл, хотя должен быть быстрым?
1. **Тяжелый `std::visit`:** Чтобы вытащить данные из варианта, компилятор под капотом строит кучу проверок и развилок (if-else или таблицы переходов). Для слабенького процессора ESP32 это оказалось тяжелее, чем просто прыгнуть по указателю в vtable.
2. **Предсказатель переходов:** Когда мы в цикле крутим массив указателей vtable одного типа, процессор ESP32 быстро понимает, куда мы прыгаем, и не тормозит конвейер.

## Что можно доработать в будущем

По идее, `std::variant` должен работать круче, потому что у него всё лежит в одном месте (**локальность данных**). Объекты в варианте создаются в одном непрерывном массиве прямо в стеке, а не разбрасываются по всей куче (heap) через `new`, как в случае с vtable. 

Чтобы раскачать скорость `std::variant`, дальше планирую проверить вот что:

1. **Посчитать кэш-промахи (Cache Misses):**
   * Из-за того, что все 250 датчиков в варианте лежат плотно друг за другом, промахов по кэшу данных (D-Cache Misses) должно быть меньше. Хочу прогнать код через эмуляторы (например, QEMU), чтобы вытащить точную статистику по кэшу и проверить эту гипотезу.
   
2. **Выкинуть `std::visit`:**
   * Попробовать переписать опрос вручную. Вместо `std::visit` взять обычный `switch-case` и проверять тип через метод `variant::index()`. Скорее всего, компилятор соберет такой код в более простой и быстрый ассемблер.
   
3. **Поиграть с размером структур:**
   * Сейчас структуры датчиков маленькие. Стоит попробовать забить их какими-нибудь тяжелыми данными (payload) и посмотреть, как изменится время.
